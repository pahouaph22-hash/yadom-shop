## เริ่มใช้งาน (ครั้งแรก)
1. **เปิด GitHub Pages:** repo → Settings → Pages → Build and deployment → Source: **GitHub Actions**
   จากนั้นแท็บ Actions → "deploy-github-pages" → Run workflow
2. **Supabase → Authentication → URL Configuration**
   - Site URL: `https://pahouaph22-hash.github.io/yadom-shop/`
   - Redirect URLs: `https://pahouaph22-hash.github.io/yadom-shop/**` และ `https://yadom-shop-one.vercel.app/**`
3. **สมัครสมาชิกด้วย `larmouamua@gmail.com`** (หรือ `pahouaph22@gmail.com`) ที่หน้า `/register` → ยืนยันอีเมล → เป็น **ผู้ดูแลระบบ** อัตโนมัติ
4. เข้า `/admin` → ตั้งค่า → เพิ่มช่องทางติดต่อ และข้อมูลการชำระเงิน
5. สินค้าและสต็อก → เพิ่มสินค้าจริง พร้อมรูป ราคาปลีก/ส่ง ต้นทุน และสต็อกเริ่มต้น
6. ให้พนักงานสมัครที่ `/register` แล้วกำหนดสิทธิ์ “พนักงาน” ในหน้าตั้งค่า

## บัญชีลูกค้า vs บัญชีพนักงาน
- **ลูกค้า (สมาชิก):** สมัครที่ `/register` (ชื่อ เบอร์ บ้าน/เมือง/แขวง ฯลฯ) และเข้าสู่ระบบที่ `/login` — ต้องเป็นสมาชิกจึงจะสั่งซื้อได้ (บังคับในฐานข้อมูลด้วย)
- **พนักงาน:** เข้าสู่ระบบที่ `/staff/login` เท่านั้น บัญชีพนักงานสร้างได้โดยแอดมินที่เมนู “พนักงานและสิทธิ์” (Edge Function `staff-admin`)
- สิทธิ์รายคน: `orders`, `products`, `customers`, `messages`, `reports`, `finance`, `settings`, `audit` — แอดมินมีทุกสิทธิ์
- บัญชีพนักงานล็อกอินหน้าลูกค้าไม่ได้ และบัญชีลูกค้าเข้า `/admin` ไม่ได้

## ความปลอดภัย
- RLS เปิดทุกตาราง · บทบาท: `admin`, `staff`, `customer`, ผู้เยี่ยมชม (anon)
- ลูกค้าเห็นเฉพาะคำสั่งซื้อของตัวเอง · ข้อมูลลูกค้าเห็นได้เฉพาะพนักงาน/แอดมิน
- ต้นทุนสินค้าไม่ถูกส่งไปหน้าร้าน (หน้าร้านอ่านผ่านฟังก์ชัน `shop_products()` เท่านั้น)
- คำสั่งซื้อ การชำระเงิน สต็อก **เขียนได้ผ่านฟังก์ชันในฐานข้อมูลเท่านั้น** ราคาคำนวณฝั่งเซิร์ฟเวอร์ ลูกค้าแก้ราคาไม่ได้
- ป้องกันซ้ำ: idempotency key ต่อการกดสั่งซื้อ (กดซ้ำ/เน็ตหลุดไม่เกิดคำสั่งซื้อซ้ำ) · เบอร์ลูกค้าไม่ซ้ำ · เลขอ้างอิงการโอนซ้ำไม่ได้ · ห้ามชำระเกินยอด · ห้ามยกเลิกคำสั่งซื้อที่ชำระแล้วโดยไม่คืนเงิน
- ตาราง `audit_log`, `payments`, `stock_movements`, `order_events` เป็น append-only
- แถวรายการสินค้าในคำสั่งซื้อไม่ถูกลบ — รายการที่เอาออกจะเหลือจำนวน 0 เพื่อเก็บประวัติ
- สินค้าใช้ soft delete · ลูกค้าที่มีคำสั่งซื้อลบไม่ได้

## สำรองและกู้คืนข้อมูล
- **ในแอป:** แอดมิน → สำรองข้อมูล → ดาวน์โหลด JSON/Excel ของทุกตาราง
- **อัตโนมัติทุกคืน:** ใส่ secret `SUPABASE_DB_URL` ใน GitHub (ดู `.github/workflows/nightly-backup.yml`)
- **กู้คืนรายการที่ลบผิด:** ประวัติการดำเนินงาน → กรอง “ลบ” → “กู้คืน”
- **Restore ทั้งฐานข้อมูล** (ไปยังโปรเจกต์ใหม่หรือหลังเกิดปัญหา):
  ```bash
  # 1) สร้าง schema: รันไฟล์ใน supabase/migrations ตามลำดับ (หรือ supabase db push)
  # 2) โหลดข้อมูล
  pg_restore --data-only --disable-triggers --no-owner -d "$SUPABASE_DB_URL" yadom-YYYYMMDD-HHMM.dump
  ```
  `--disable-triggers` จำเป็นเพราะตารางประวัติถูกล็อกไม่ให้แก้ไข
